## 1. Как правильно закончить работу

**Не нужно удалять контейнер и не нужно удалять базу.**

Когда закончил работать, просто останови контейнер:

```bash
docker compose stop
```

После этого:

```bash
docker compose ps
```

контейнер будет существовать, но будет остановлен.

Данные при этом **останутся** благодаря:

```yaml
volumes:
  - yeticave_mysql_data:/var/lib/mysql
```

То есть:

```text
docker compose stop
        ↓
MySQL остановился
        ↓
данные остались
```

Можно спокойно закрывать PhpStorm, терминал, компьютер и т.д.

# 3. Но есть ещё более удобная команда

Вместо:

```bash
docker compose start
```

можно использовать:

```bash
docker compose up -d
```

Я бы **тебе рекомендовал именно её**.

Почему?

`up -d` говорит:

> «Убедись, что всё описанное в `compose.yaml` запущено».

Если контейнер уже существует — запустит его.

Если контейнера почему-то нет — создаст его.

Поэтому твой ежедневный сценарий может быть просто:

```bash
docker compose up -d
```

А закончить:

```bash
docker compose stop
```

Получается:

```text
НАЧАЛО РАБОТЫ
docker compose up -d
        ↓
работаешь
        ↓
КОНЕЦ РАБОТЫ
docker compose stop
```

# 4. Очень важно: `stop` и `down` — разные вещи

Вот это тебе сейчас желательно запомнить.

### `stop`

```bash
docker compose stop
```

Просто:

> остановить контейнеры.

Данные остаются.

Потом:

```bash
docker compose start
```

и продолжаешь работу.

---

### `down`

```bash
docker compose down
```

Это уже:

> убрать созданные Compose-контейнеры и сеть.

Но **именованный volume по умолчанию тоже останется**.

То есть в твоём случае:

```text
docker compose down
        ↓
контейнер удалён
        ↓
volume yeticave_mysql_data остался
        ↓
docker compose up -d
        ↓
новый контейнер подключит старые данные
```

Поэтому `down` тоже не страшен сам по себе.

Но для ежедневной работы он тебе **не нужен**.

---

### А вот это уже опаснее:

```bash
docker compose down -v
```

`-v` означает удалить volumes.

А значит:

```text
yeticave_mysql_data
        ↓
УДАЛЁН
        ↓
данные MySQL потеряны
```

Для учебного проекта это означает фактически начать БД заново.

Поэтому пока запомни:

```text
stop       → просто выключить
up -d      → запустить
down       → удалить контейнеры
down -v    → удалить контейнеры + данные
```

# 5. А что делать с Database Tool в PhpStorm?

Его **закрывать отдельно не надо**.

Можешь закрыть PhpStorm.

Когда завтра откроешь проект, Database Tool может показывать подключение, но MySQL пока будет недоступен, если контейнер остановлен.

Запускаешь:

```bash
docker compose up -d
```

и снова всё работает.

Если PhpStorm покажет красный значок подключения — это просто потому, что в момент открытия контейнер ещё не был запущен. После запуска можно сделать **Reconnect**.

## И ещё один важный момент именно для этого задания

Не стоит сейчас просто копировать приведённое решение HTML Academy.

Лучше написать `queries.sql` самому, а Database Tool использовать как лабораторию:

```text
ТЗ
 ↓
пишешь SQL в queries.sql
 ↓
запускаешь его через PhpStorm
 ↓
смотришь результат
 ↓
если ошибка — разбираешь
 ↓
исправляешь queries.sql
```

И тогда ты действительно поймёшь `INSERT`, `SELECT`, `JOIN`, `WHERE`, `ORDER BY`, `UPDATE`, а не просто получишь принятое задание.

**На текущем этапе твой ежедневный ритуал буквально такой:**

```bash
# начал работу
docker compose up -d

# ... работаешь в PhpStorm ...

# закончил
docker compose stop
```

И всё. Базу заново создавать, `schema.sql` каждый раз выполнять и Docker заново настраивать **не нужно**.
